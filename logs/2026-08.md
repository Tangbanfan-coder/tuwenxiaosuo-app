## 2026-08-18 — 写作结构化输出与对白 JSON 兼容修复

- 目标：修复文本中转站返回人物对白时，ASCII 双引号未转义导致写作 JSON 失效并提示“结构化结果不完整”的问题，同时兼顾 OpenAI 官方、常见兼容中转与严格过滤参数的中转站。
- 关键改动：在统一供应商能力层新增 `structuredOutput`，自动兼容使用覆盖面较广的 `json_object`，OpenAI 官方使用严格 `json_schema`，严格中转保留纯提示词协议，自定义设置可显式选择；前台流式/非流式写作与 Android 后台写作复用同一个请求构造，不支持时不自动重发，避免重复计费。严格 schema 覆盖正文、场景记忆与视觉计划，所有对象均关闭额外字段并要求已声明字段；无图模式不包含 `visual_plan`。旧版官方/严格预设即使没有新字段，也继续兑现各自的 schema/纯提示词行为。
- 提示与诊断：系统提示要求对白优先使用中文弯引号，ASCII 双引号与控制字符必须按 JSON 规则转义；结果解析区分“对白引号未转义”“JSON 尾部截断”“其他格式错误”，提示不泄露模型正文。损坏段落不再把未转义引号前的半段误当作完整正文，已闭合的前序段落仍可安全恢复。
- 原因：旧链路只用提示词要求 JSON，接口层没有结构化约束；模型或中转站在正文字符串中写入裸英文双引号后，严格 `JSON.parse` 必然失败。自动探测中转站是否支持 schema 没有可靠元数据，失败后自动改参数重试又可能重复计费，因此采用显式能力分层而非猜测或自动重发。
- 验证：OpenAI 官方文档确认 `json_schema` 保证 schema 一致、`json_object` 保证合法 JSON；定向 `vitest` 6 文件 / 86 项通过，补充返工后核心 4 文件 / 73 项通过；`npx tsc -b --pretty false`、`npm run build`、`npm run android:sync`、Android `:app:assembleDebug` 与 `git diff --check` 通过。Debug APK 为 7,382,619 字节，SHA-256 `C2FB509DE22B8495328DA146C1E9880057B53BE41D6FE19D21C1519E42789D37`。全量 `npm test -- --testTimeout=30000` 为 51 文件中 50 个通过、482 项中 480 项通过，2 项失败均位于未改动的 `App.test.tsx`，仍查询旧按钮名“保存已发送内容”，而当前用户消息底部编辑抽屉已显示“保存修改”，与本批无关。

## 2026-08-13 — Android 流式双状态源修复（设置页与实际传输方式统一）

- 根因：Android 流式输出存在两个状态源——设置页开关直接读写 `androidStreamingEnabled`，而请求执行由 `resolveTextTransport`（forceNonStream > textTransport > 调用点默认）决策。`textTransport=stream`（OpenAI 官方预设）时开关状态与真实传输脱节（开关显示"已关闭"但实际走 WebView 流式）；`textTransport=non-stream`（严格中转）时开关可操作但不生效；用户无法获知"由兼容预设决定"。
