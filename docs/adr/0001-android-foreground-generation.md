# ADR 0001：Android 前台服务承接长时 AI 生成

- 状态：已采纳
- 日期：2026-08-12

## 背景

Android 将应用切到后台后，WebView 的网络请求、流式读取和 JavaScript 执行可能被暂停或终止。上游请求可能已经接收并计费，但本地因未继续读取响应而把文本或图片标记为失败。各类 OpenAI 兼容中转站的异步任务、查询接口和幂等能力并不统一，不能作为通用恢复契约。

## 决策

Android 上的文本和图片生成统一交给应用内 `dataSync` 前台服务执行，WebView 只负责创建任务、观察持久化状态和消费结果。

- 原生任务状态为 `prepared / running / completed / failed / unknown`。
- API Token 仅通过启动 Intent 和服务内存传递，不写入任务文件、结果文件或错误信息。
- `prepared` 表示请求尚未进入执行阶段；重启恢复时可确定为失败。`running` 表示请求可能已经到达上游；若进程中断且没有完整结果，只能标记 `unknown`。
- `unknown` 永不自动重发，避免重复计费；由用户决定是否重新生成。
- 文本请求使用非流式 OpenAI 兼容响应，原始 JSON 经 Token 脱敏后原子落盘，再由前端解析并在 Dexie 事务中消费。
- 图片继续复用原生图片生成、鉴权、下载、格式校验和原子替换逻辑，前端只接收本地 URI。
- 写作 notice 保存 `backgroundTaskId`。notice 的 `ready` 状态是结果已被本地事务消费的幂等标记；业务数据库临时失败时不确认原生任务，后续启动继续消费。
- 原生任务文件采用临时文件、备份文件和目标文件替换；完整文本响应已落盘但任务状态尚未更新时，启动扫描可恢复为 `completed`。

## 取舍

该方案不依赖任一中转站提供异步任务接口，且能覆盖普通切后台场景。代价是 Android 会显示持续通知，文本失去前端逐字流式显示，并增加原生任务状态与本地结果消费逻辑。

前台服务不能保证强制停止、设备重启、系统或厂商强杀后的网络请求继续运行。如果请求已经进入 `running`，但完整响应尚未落盘，本地无法证明上游是否完成，因此只能保留 `unknown`，不能自动补发或找回上游结果。

## 备选方案

1. 保持 WebView 请求并增加生命周期保活：实现简单，但无法可靠抵抗后台暂停和进程终止，不能解决已计费结果丢失。
2. 要求所有中转站支持异步任务 ID 和结果查询：恢复能力更强，但接口差异大，无法作为通用兼容层。
3. 自建服务端任务代理：可获得最完整的持久化、幂等和查询能力，但会引入服务端成本、密钥托管和运维责任。若未来需要跨设备恢复或强制停止后继续收取结果，应迁移到该方案。
