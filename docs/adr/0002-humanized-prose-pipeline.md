# ADR 0002：去 AI 味采用生成约束、检测、定向重写与风格语料分层

- 状态：已采纳
- 日期：2026-08-13

## 背景

仅靠不断增长的常驻提示词禁止 AI 高频句式，会持续占用上下文，并在长上下文中降低约束效果。把模型输出统一交给第二次全文改写，又会增加延迟和费用，并可能改变剧情事实、人物关系、伏笔或用户已经看到的流式正文。现有系统已经具备稳定段落 ID、Bigram BM25 剧情检索、渐进式上下文压缩和段落反馈，需要在这些边界上增加可验证的小说文风治理，而不是建立一套旁路写作系统。

社区 Humanizer、中文编辑和小说 Skill 提供了模式目录、事实保护、质量门禁与人物声纹等可借鉴机制，但大多仍以长提示词或全文重写为主，且部分规则面向百科、宣传稿而非小说，不能原样成为运行时契约。

## 决策

去 AI 味拆为四个独立责任，并分阶段交付：

1. **默认生成约束**：系统提示只保留短小的小说写作原则，默认生效且无需用户确认。它属于可被用户本轮明确文体要求覆盖的风格倾向，不进入安全、结构化输出或事实一致性的不可覆盖规则。
2. **本地规则检测**：模型生成完成后由纯本地规则扫描正文，输出绑定稳定段落锚点的结构化命中。规则包含稳定 ID、类别、严重度、阈值、例外、说明和重写目标；模式用于编辑诊断，不用于鉴定文本是否由 AI 创作。首阶段不自动修改正文。
3. **用户触发的定向重写**：用户从命中段落主动请求建议稿，独立模型调用只接收原段落、必要相邻上下文、命中规则、受保护约束和少量相关风格范例。重写不得新增或删除情节事实。采用建议稿时由单一数据库事务同时更新正文消息、消息段落指纹、章节正文和章节段落索引，避免显示正文与后续检索漂移。
4. **统一风格语料库**：用户语料原文只保存一次，来源、片段和使用范围分开建模。首阶段产品只开放全局语料；绑定契约预留 `global / project`、排除状态和权重，以便未来增加作品范围而不复制正文。内置内容只包含规则正反例，不包含现代小说原文。

语料导入采用“辅助整理”：应用先按章节、空行和自然段确定性拆分并生成稳定 ID 与指纹，AI 只能建议片段组合和标签，不能改写语料原文。用户可以修改标签后确认；模型不可用时仍可手动保存。语料文本在提示中始终作为不可信风格数据，不能获得指令权限。

风格检索与现有剧情检索保持不同数据源和契约。实现可以复用中文 bigram、BM25 评分和稳定排序思想，但不能把风格片段伪装为历史剧情段落。候选由语言与明确排除条件硬过滤，再按题材、场景、视角、节奏、叙述距离、技巧、词面相关性和用户偏好软排序，并加入去重和重复使用惩罚。每轮只注入少量完整范例，且可随上下文压力裁剪。

## 不变量

- 现有写作 JSON 格式、上下文预算硬校验、流式正文投影、后台结果恢复、剧情 Retriever、伏笔、摘要、反馈、角色和插画契约保持兼容。
- 默认行为只检测，不自动重写；任何额外模型调用必须由用户明确触发。
- 检测规则只有一个权威实现，UI 不复制匹配和评分逻辑。
- 重写失败或被拒绝时原文保持不变；采用建议稿后所有正文索引在同一事务内一致更新。
- 语料原文、AI 标签建议和用户确认状态分开保存；AI 不得通过重新输出文本改变原始语料。
- 删除作品只删除未来的作品绑定，不删除全局语料来源和片段。

## 取舍

该方案比单一提示词或全文自动 Humanizer 增加了数据模型、检测结果展示、定向调用和事务更新，但每层可以独立测试，用户能够通过原文与建议稿对比判断效果，也能逐步积累接受和拒绝数据。首阶段不会获得完全无感的自动润色体验；待规则误报率、重写采纳率和事实保持评测足够稳定后，才考虑对少数高置信度规则开放可选自动模式。

作品独立语料库暂不开放。统一全局库配合作品风格画像和动态场景检索可以覆盖大部分需求，同时避免数据复制和双重管理。若真实使用出现跨题材污染、隐私隔离或强风格固定需求，再通过已预留的绑定契约增加作品范围。

## 备选方案

1. **长常驻 Humanizer 提示词**：实现最快，但上下文成本持续增长，规则难以解释、统计和按场景裁剪。
2. **生成后自动全文重写**：用户无需操作，但延迟、费用和事实漂移风险最高，也无法直接观察修改是否有效。
3. **仅本地字符串替换**：成本低且确定，但自然语言规则存在大量例外，机械替换容易破坏语义和人物声口。
4. **物理分离的全局库和作品库**：隔离直观，但会复制语料、分裂检索逻辑，并增加删除、提升范围和去重的同步责任。
